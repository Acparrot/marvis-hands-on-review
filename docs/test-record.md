### 结果标记

- **成功**：核心目标完成，且有可复核结果。
- **部分成功**：主要步骤已执行，但产物、反馈或自动化程度与预期有差异。
- **证据不完整**：可以看到部分过程，但证据不足以确认全链路。

## T01：模糊语义检索项目资料

**指令**

> 我们之前是不是讨论过大学生市场？最后为什么没做？

**预期**

- 不依赖准确文件名或文件路径。
- 找到与“大学生市场”相关的本地资料。
- 根据资料回答“为什么没做”。

**实际结果：成功**

- Marvis 首先区分了对话记录与本地文件，指出对话中没有完整记录。
- 它随后找到多份月度记录和复盘资料，生成时间线。
- 输出的暂停原因包括获客成本超过预算和付费意愿不足。

**证据**

- [用户的模糊问法](../assets/images/01-fuzzy-query.png)
- [找到的本地资料](../assets/images/02-local-files-found.png)
- [生成的时间线与结论](../assets/images/03-result-summary.png)

**备注**

测试使用的项目文件为专门准备的演示资料，不代表真实商业项目数据。

## T02：文件名无法提供时的内容检索

**指令**

> 我是不是存过一份讲为什么休息也会像完成任务的资料？

**预期**

- 即使文件名与内容无关，也能根据语义定位。
- 读取内容并输出可用摘要。

**实际结果：成功**

- Marvis 定位到文件名与主题无关的目标文件。
- 它概括出“休闲活动被目标化和绩效化后，可能再度变成任务”这一核心观点。
- 当问法变为“我在哪里讲过”时，它改用历史对话检索，说明问法会影响数据源选择。

**证据**

- [通过内容找到目标文件](../assets/images/04-opaque-name-search.png)
- [历史对话检索的对照结果](../assets/images/05-history-contrast.png)

## T03：学习资料整理与定时复习

**指令摘要**

> 找到通过 QQ 传入的课件、笔记和课堂照片；按需求分析与 MySQL 分类；生成总结并放到 D 盘学习目录；三分钟后提醒，并打开需求分析的总结和笔记。

**预期**

- 找到并识别不同格式的资料。
- 根据科目分类，生成两份总结。
- 所有产物保存在指定的 D 盘目录。
- 到点有可见提醒，并自动打开指定文件。

**实际结果：部分成功**

- 成功读取三周需求分析笔记和 MySQL 题目图片，生成两份摘要。
- 成功建立科目目录、定时任务，并在到点后打开文件。
- 首次生成的总结默认保存到 C 盘内的工作区，没有直接落到用户指定目录。
- 用户追加指令后，文件被归入相应目录，并生成了补充教学文档。
- 到点后有文件打开动作，但缺少预期中醒目、独立的提醒通知。

**证据**

## T04：游戏准备与硬件诊断

**指令摘要**

> 提前准备并打开《双人成行》；检查当前电脑配置是否适合运行，并给出优化建议。

**预期**

- 找到游戏并进入可开始状态。
- 读取硬件配置，判断是否达到要求。
- 如需修改系统或关闭程序，先征求用户确认。

**实际结果：部分成功**

- 游戏成功启动，但登录和应用内状态需要用户确认。
- Marvis 读取到 i5-12600KF、RTX 4060 和 32GB 内存，判断硬件足以运行。
- 诊断报告将掉帧原因归纳为电源模式、后台程序和游戏画面设置，并给出手动操作建议。
- 对修改电源模式等操作，系统保留了人工选择和确认环节。

**证据**

- [游戏状态确认](../assets/images/12-game-preparation.png)
- [游戏启动](../assets/images/13-game-launched.png)
- [硬件要求与优化范围](../assets/images/14-hardware-recommendation.png)
- [掉帧诊断与建议](../assets/images/15-diagnosis-report.png)

**未计入结论的证据**

素材中有一张另一款游戏的更新画面，与本测试目标不一致，因此未用来证明《双人成行》已自动更新。

## T05：手机远程任务派发

**目标**

从手机端向电脑派发任务，并观察电脑端执行过程。

**实际结果：证据不完整**

现有证据可以说明电脑端接收并执行了准备游戏的任务，但缺少手机端发出指令、跨端状态同步和手机接管画面的完整记录。因此本项不标记为成功。

## T06：本地模式与隐私主张

**官方能力说明**

Marvis 官方网站称本地模式使用端侧大模型，文件不上传。

**验证目标**

- 完成本地模型组件部署。
- 在断网状态下完成对话和本地文件解析。
- 观察执行期间的网络请求，验证文件数据是否离开本机。

**实际结果：未完成闭环**

- 进入了腾讯应用宝移动应用引擎的安装确认阶段。
- 检查了当时本机存储空间。
- 没有完成部署、断网测试和网络流量检查，不足以独立证实隐私实现。

**证据**
